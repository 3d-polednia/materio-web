2. ZASADA: NIE ZMIENIAJ FUNKCJONALNOŚCI
Rebranding nie jest refaktoryzacją aplikacji.
Nie dodawaj nowych funkcji biznesowych.
Nie przebudowuj architektury.
Nie zmieniaj logiki kalkulatorów.
Nie zmieniaj modelu użytkowników.
Nie zmieniaj Firebase/Firestore bez konkretnej konieczności.
Nie zmieniaj istniejących funkcji tylko dlatego, że można je ulepszyć.
Zakres tej sesji:
BRANDING + UI BRANDINGU + ASSETY + SEKCJA APLIKACJI NA WEB

3. KRYTYCZNE: NIE ZMIENIAJ APPLICATION ID
Jeżeli obecna aplikacja jest już opublikowana w Google Play, zachowaj istniejący:
• applicationId
• package name
• identyfikator aplikacji w Google Play
• istniejącą bazę Firebase powiązaną z aplikacją
Nie twórz nowej aplikacji tylko dlatego, że zmieniamy nazwę marki.
Celem jest:
aktualizacja istniejącej aplikacji Materio → LiczMat
a nie publikacja drugiej aplikacji.
Jeżeli gdziekolwiek występuje ryzyko, że zmiana spowoduje utworzenie nowej aplikacji w Google Play, zatrzymaj się i zgłoś to przed wykonaniem zmiany.

5. IDENTYFIKACJA STAREJ MARKI
Przeszukaj cały projekt pod kątem:
text
Materio
materio
MATERIO
materio-app.com
pl.materio.app

oraz innych oczywistych wariantów starej marki.
Dla każdego znalezionego wystąpienia określ:
1. Czy jest widoczne dla użytkownika?
2. Czy jest częścią konfiguracji technicznej?
3. Czy można je bezpiecznie zmienić?
4. Czy musi pozostać ze względów technicznych?
Ważne
Nie zmieniaj automatycznie technicznych identyfikatorów tylko dlatego, że zawierają „materio”.
Szczególnie nie zmieniaj bez potrzeby:
• applicationId,
• package name,
• identyfikatorów Firebase,
• istniejących identyfikatorów baz danych,
• kluczy API,
• nazw kolekcji Firestore,
• istniejących identyfikatorów użytkowników,
• innych identyfikatorów, których zmiana mogłaby spowodować utratę kompatybilności.
Widoczna marka ma być LiczMat.
Techniczna kompatybilność istniejącej aplikacji ma zostać zachowana.

Nie używaj starych screenshotów tylko dlatego, że są już dostępne.

9. SEKCJA „APLIKACJA” NA LICZMAT.COM
Na stronie internetowej dodaj profesjonalną sekcję/stronę:
Aplikacja
Jeżeli architektura istniejącego projektu posiada już odpowiednią stronę lub sekcję, wykorzystaj ją zamiast tworzyć duplikat.
Cel
Użytkownik ma zrozumieć:
LiczMat działa również jako aplikacja Android.
Ale strona nie może wyglądać jak reklama aplikacji, w której web jest tylko dodatkiem.
To nadal jest:
platforma LiczMat
a aplikacja jest jednym ze sposobów korzystania z niej.

10. TREŚĆ SEKCJI „APLIKACJA”
Sekcja powinna jasno komunikować wartość aplikacji.
Powinna zawierać między innymi:
Nagłówek
LiczMat na Androida
Krótkie wyjaśnienie
Aplikacja LiczMat pozwala korzystać z najważniejszych funkcji platformy również na telefonie.
Nie używaj komunikacji sugerującej, że użytkownik musi mieć aplikację.
Web pozostaje dostępny bez instalowania aplikacji.

12. SCREENSHOTY NA STRONIE
Sekcja aplikacji powinna prezentować rzeczywiste screenshoty aktualnej aplikacji LiczMat.
Nie używaj:
• screenshotów Materio,
• starych logo,
• grafik z poprzednią nazwą,
• nieaktualnych ekranów,
• przypadkowych stockowych ekranów aplikacji.
Jeżeli potrzeba, przygotuj nowe screenshoty na podstawie aktualnej aplikacji.
Screenshoty powinny być spójne wizualnie z LiczMat.com.

14. RESPONSYWNOŚĆ
Sekcja „Aplikacja” musi działać prawidłowo:
• desktop,
• tablet,
• telefon.
Na telefonie screenshoty aplikacji nie mogą powodować:
• poziomego scrollowania,
• wychodzenia poza ekran,
• przesuwania layoutu,
• zbyt dużych odstępów,
• problemów z CTA.

• DE,
• EN,
• UK,

Nie przenoś jeszcze całego serwisu z:

na:

Jeżeli w kodzie znajdują się stare URL-e, zmieniaj je tylko wtedy, gdy są częścią widocznej marki lub istnieje bezpieczna możliwość przygotowania ich do późniejszej migracji.
Nie wykonuj pochopnej globalnej zamiany domeny.
